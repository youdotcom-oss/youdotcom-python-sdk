# Release

Release a new version of the `youdotcom` Python SDK to PyPI and GitHub.

The SDK is hand-maintained (no longer generated by Speakeasy). This skill
covers version bumping, changelog updates, testing, and opening a release PR.

## Step 1: Check current versions

```bash
git fetch --all --tags
gh release list --repo youdotcom-oss/youdotcom-python-sdk --limit 1
curl -s https://pypi.org/pypi/youdotcom/json | python3 -c "import sys,json; print(json.load(sys.stdin)['info']['version'])"
```

Read the version from `pyproject.toml` (line 3) and `src/youdotcom/_version.py`.

Present a summary:
- GitHub release: latest tag
- PyPI version: latest published
- Local version: in pyproject.toml and _version.py
- Unreleased commits: `git log <latest-tag>..HEAD --oneline`

## Step 2: Confirm the next version

Analyze unreleased commits to determine the semver bump:
- **patch** (X.Y.Z+1): bug fixes, dependency updates, docs
- **minor** (X.Y+1.0): new features, non-breaking additions
- **major** (X+1.0.0): breaking API changes, removed endpoints

Use `AskUserQuestion` to confirm the version with the user. Do NOT proceed until confirmed.

## Step 3: Create a release branch

```bash
git checkout -b release/X.Y.Z
```

## Step 4: Update version

Update the version string in:
- `pyproject.toml` — `version = "X.Y.Z"`
- `src/youdotcom/_version.py` — `__version__: str = "X.Y.Z"` (`__user_agent__` is derived automatically)

## Step 5: Update documentation

### CHANGELOG.md

Add a new section at the top, following Keep a Changelog format:

```markdown
## [X.Y.Z] - YYYY-MM-DD

### Added
- ...

### Changed
- ...

### Removed
- ...
```

Analyze `git diff <previous-tag>..HEAD` to determine what changed.

### MIGRATION.md

Only update if there are breaking changes. Add a migration section with before/after code examples.

### README.md

Update the error class count, method count, and any examples if the API surface changed.

## Step 6: Run tests

### Start the mock server

```bash
cd tests/mockserver && go build -o mockserver . && ./mockserver &
sleep 1
cd ../..
```

### Unit tests

```bash
.venv/bin/python -m pytest tests/ --ignore=tests/test_live.py --ignore=tests/test_performance.py -v
```

### Performance tests

```bash
.venv/bin/python -m pytest tests/test_performance.py -v
```

### Type checking

```bash
.venv/bin/mypy src/youdotcom/
```

### Live tests (if API key available)

```bash
YDC_API_KEY=... .venv/bin/python -m pytest tests/test_live.py -v
```

### Stop the mock server

```bash
kill $(lsof -ti:18080)
```

All tests and mypy must pass before committing.

## Step 7: Verify server URLs

```bash
# Default server (answer, research, finance_research) = api.you.com
grep "api.you.com" src/youdotcom/sdkconfiguration.py
# Search/contents servers = ydc-index.io
grep "ydc-index.io" src/youdotcom/models/searchop.py src/youdotcom/models/contentsop.py
```

Search and contents methods use `SEARCH_OP_SERVERS[0]` / `CONTENTS_OP_SERVERS[0]` explicitly. Answer, research, and finance_research use the default `SERVERS[0]`.

## Step 8: Verify hand-maintained files

These files are hand-maintained and must not be lost:
- `src/youdotcom/_shims.py` — backward-compat shims (`SearchShim`, `ContentsShim`)
- `src/youdotcom/research_helpers.py` — background-mode research helpers
- `src/youdotcom/errors/paymentrequired_response_error.py` — 402 error class

## Step 9: Commit, push, and open PR

```bash
git add -A
git commit -m "Release vX.Y.Z: <brief summary>"
git push -u origin release/X.Y.Z
```

Open a PR against `main`:

```bash
gh pr create --base main --head release/X.Y.Z \
  --title "Release vX.Y.Z: <brief summary>" \
  --body "<changelog summary>"
```

Report the PR URL to the user.
